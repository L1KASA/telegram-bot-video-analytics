# Telegram Bot Video Analytics

Бот для аналитики видео-контента, использующий LLM (Ollama) для преобразования запросов на естественном языке в SQL-запросы.

## Архитектура

Проект следует принципам **Clean Architecture**, разделяя ответственность по слоям. Это обеспечивает независимость бизнес-логики от фреймворков и баз данных.

### Структура папок (`src`)

- **`src/domain`**: Ядро бизнес-логики.
    - `services`: Абстрактные интерфейсы сервисов (например, `NLUService`).
    - `value_objects`: Объекты-значения (AnalyticsQuery, типы метрик).
    - `prompts`: Логика построения и хранения промптов для LLM.
    - `schemas`: Pydantic схемы для валидации данных (например, ответов LLM).
- **`src/infrastructure`**: Реализация интерфейсов и работа с внешним миром.
    - `database`: ORM модели (SQLAlchemy) и репозитории.
    - `llm`: Клиент к Ollama и реализация сервиса `OllamaNLUService`.
    - `telegram`: Хендлеры и middleware для `aiogram`.

### Ключевые особенности
- **Независимость от LLM**: Система использует интерфейс `NLUService`. Чтобы заменить Ollama на OpenAI, достаточно написать новую реализацию адаптера в `infrastructure/llm` и подменить её в фабрике.
- **Безопасность**: Бот **не** позволяет LLM генерировать SQL напрямую. LLM возвращает JSON-структуру (Intermediate Representation), которая валидируется и затем транслируется в SQL через безопасный репозиторий.

## Принцип работы LLM

LLM используется как **семантический парсер**.

1. **Запрос**: Пользователь пишет: *"Сколько видео набрало больше 100к просмотров?"*
2. **Промпт**: Бот формирует системный промпт, включающий:
   - Описание схемы данных (`videos`, `video_snapshots`).
   - Правила выбора таблицы (статика vs динамика).
   - Примеры (Few-Shot Learning).
3. **Генерация**: LLM возвращает строго структурированный JSON:
   ```json
   {
     "entity": "video",
     "aggregation": "count",
     "metric": "views_count",
     "filters": {"metric_gt": 100000}
   }
   ```
4. **Валидация**: `OllamaNLUService` проверяет JSON через Pydantic-схему `LLMResponseSchema`.
5. **Выполнение**: `AnalyticsRepository` строит безопасный SQL-запрос на основе валидированного объекта.

## Установка и Запуск

### Предварительные требования
- **Docker** и **Docker Compose**
- Python 3.12
- Ollama

### 1. Настройка окружения
Скопируйте пример файла конфигурации и укажите в этом файле актуальные параметры:
```bash
cp .env.example .env
```

### 2. Запуск через Docker
```bash
docker-compose up --build
```
Эта команда:
1. Поднимет контейнер с PostgreSQL.
2. Применит миграции (alembic upgrade).
3. Запустит бота.

---

## Миграции Базы Данных (Alembic)

Мы используем **Alembic** для управления схемой БД.

### Как создать новую миграцию
Если вы изменили модели в `src/infrastructure/database/models.py`:

1. Убедитесь, что БД запущена.
2. Выполните команду генерации миграции (лучше делать локально, настроив .env на localhost):
   ```bash
   alembic revision --autogenerate -m "описание изменений"
   ```
### Чтобы обновить базу данных до актуального состояния:

```bash
docker compose exec bot alembic upgrade head
```
*Примечание: При запуске через `docker-compose`, миграции применяются автоматически.*

## Посев данных из json
### Скрипт `src/seed.py`:
1. Парсит JSON.
2. **Очищает** текущие таблицы `videos` и `video_snapshots`.
3. Записывает новые данные пачками по 100 записей.
### Подготовка данных
Файл с данными должен называться `videos.json` и лежать в корне проекта.
Пример структуры `videos.json`:
```json
[
  {
    "id": "uuid...",
    "creator_id": "...",
    "views_count": 100,
    "snapshots": [ ... ]
  }
]
```

#### Команда для запуска:
Если бот уже запущен в контейнере `bot`:
```bash
docker-compose exec bot python -m src.seed
```
